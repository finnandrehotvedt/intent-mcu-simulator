Intent MCU Simulator browser-session API protocol
Version: intent-mcu-browser-session-request@1
Public Lab: https://lab.teachthecompany.com/
Endpoint: POST https://lab.teachthecompany.com/api/session/v1
Reference client: https://lab.teachthecompany.com/api/session/v1/client.mjs

The API is off by default in every browser tab. The user opens API access and
creates one temporary, one-use pairing. The secret must never enter a prompt,
chat, URL, command argument, log or source control. The Lab-generated local
.intentpair ticket is the sole secret-bearing file exception: it is short-lived,
one-use, must never be shared, and the reference client deletes it immediately
after strict parsing. Hidden stdin remains a legacy local fallback.

Transport operations
owner.register, owner.heartbeat, pairing.create, pairing.claim,
request.submit, owner.pull, owner.authorize, owner.complete, result.read,
owner.revoke.

Client transport examples
Claim the one-use pairing (the secret belongs only in this HTTPS JSON body,
supplied from the deleted local ticket or hidden-input fallback; never put it
in a URL, ordinary plan or log):
POST /api/session/v1
{"operation":"pairing.claim","pairingSecret":"<hidden local input>","scopes":["discover","read_project"]}
Success returns {"ok":true,"code":"API_CLIENT_PAIRED","sessionId":"...",
"projectId":"...","revision":0,"clientCapability":"...","scopes":[...] }.
Keep clientCapability only in process memory and send it as
Authorization: Bearer <clientCapability>.

Queue one request:
{"operation":"request.submit","sessionId":"<sessionId>","request":{
"schema":"intent-mcu-browser-session-request@1","request_id":"unique-id",
"session_id":"<sessionId>","project_id":"<projectId>",
"expected_revision":0,"sequence":1,"command":"project.inspect",
"arguments":{}}}
Success returns {"ok":true,"code":"API_REQUEST_QUEUED","request_id":"..."}.

Read its result:
{"operation":"result.read","sessionId":"<sessionId>","requestId":"unique-id"}
While pending the code is API_RESULT_PENDING. A terminal owner result includes
schema intent-mcu-browser-session-result@1, the matching request_id, status,
code, revision_before, revision_after and changes; command-specific fields are
included alongside them. A terminal result is consumed once.

Client request envelope
{
  "schema": "intent-mcu-browser-session-request@1",
  "request_id": "unique client ID",
  "session_id": "returned by pairing.claim",
  "project_id": "returned by pairing.claim",
  "expected_revision": 0,
  "sequence": 1,
  "command": "project.inspect",
  "arguments": {}
}

Scopes
discover and read_project are the default read-only scopes. edit_circuit is a
separate user opt-in for the selected canonical profile. The ATmega328P uses
its canonical editor. RP2040 Pico, ESP32-C3 and STM32F429ZI accept only their
existing bounded series-LED models, exact named pins and profile validators.
No support is inferred across profiles.

Discovery and read commands
capabilities.list, components.catalog, project.inspect, components.list,
component.pins, nets.list, circuit.validate.

Edit commands
edit.batch accepts exactly {"commands": [...]} and at most 16 operations.
Supported operations are component.add, component.remove,
component.property.set, wire.connect, and wire.disconnect. A wire.disconnect
with only net_id removes the whole net; adding endpoint removes one branch.
Connections use stable component IDs and named pins.
The complete batch validates and commits as one transaction or changes
nothing. edit.undo and edit.redo accept exactly the server-returned
transaction_id and only operate when that transaction is still at the history
head.

Nonsecret reference-client plan
Omitting a plan makes the client read-only. An edit plan is ordinary nonsecret
JSON and contains no pairing secret or capability:
{"schema":"intent-mcu-browser-session-plan@1","commands":[...]}
The client rejects component.remove unless the top-level field
"allow_component_removal":true is explicitly present. It never removes,
replaces or resets a project by default and never automatically undoes.

Optional same-process session
Run `node client.mjs --session pairing.intentpair` to claim one ticket once and
keep the resulting capability only in that live process. Send one nonsecret
JSON object per line: `{"command":"inspect"}`,
`{"command":"apply","plan":{...}}`,
`{"command":"undo","transaction_id":"<exact server ID>"}`, or
`{"command":"close"}`. The process may perform successive bounded plans
without another pairing while the existing owner, scope, revision, rate, idle
and absolute-lifetime rules remain valid. Process exit, reload, revoke, expiry
or authority loss requires a fresh pairing; no capability is persisted.
The caller must launch this as a real keep-open process with writable stdin and
retain its process/session handle across later AI chat turns. A detached command
with closed stdin fails with API_SESSION_STDIN_REQUIRED before the ticket is
read or deleted. Wait for the first `mode:"session"` JSON line, then send every
later command through that exact process handle; never relaunch the consumed
ticket. For ongoing Codex work, launch session mode through exec_command with
tty:true, retain its session_id, and send later JSONL commands through
write_stdin. Do not fall back to one-shot ticket commands. Session mode sends a quiet authenticated client heartbeat every 60
seconds. It renews the 120-second idle lease and bounded 15-minute renewal
horizon only while the original browser owner tab is independently alive and
heartbeating. Closing the process, closing or reloading the tab, Revoke, two
missed heartbeats or authority loss still fails closed. No capability is
written to disk, cookie or browser storage, and one-shot mode does not renew.

Exact batch operation shapes
{"command":"component.add","id":"part-1","type":"led.basic-v1",
 "position":{"x":0.7,"y":0.4,"rotation":0}}
{"command":"component.remove","component_id":"part-1"}
{"command":"component.property.set","component_id":"part-1",
 "key":"resistance_ohms","value":220}
{"command":"wire.connect","net_id":"signal-1",
 "from":{"component":"board-1","pin":"D13"},
 "to":{"component":"resistor-1","pin":"A"}}
{"command":"wire.disconnect","net_id":"signal-1"}
{"command":"wire.disconnect","net_id":"signal-1",
 "endpoint":{"component":"resistor-1","pin":"A"}}

The edit request uses command "edit.batch" and arguments
{"commands":[<one to sixteen operations>]}. API_BATCH_COMMITTED returns the
server transaction_id. A later, separate explicit Undo request uses command
"edit.undo" and arguments {"transaction_id":"<server transaction_id>"} in
the same live in-memory session. Enter keeps the change; only typing UNDO into
the reference client sends that Undo request.

Revision and concurrency rules
Every command uses the current exact project_id, monotonically increasing
sequence and latest expected_revision. Read the revision_after returned by each
result before submitting the next request. API_STALE_REVISION,
API_PROJECT_CHANGED and transaction conflicts require fresh discovery; never
guess or silently retry a mutation. Reload, Open, New, profile change, revoke,
expiry or project replacement removes the old authority.

Stable result and error families
API_AUTH_REQUIRED, API_SCOPE_REQUIRED, API_PROFILE_READ_ONLY,
API_PAIRING_EXPIRED, API_CLIENT_GONE, API_OWNER_GONE, API_STALE_REVISION,
API_PROJECT_CHANGED, API_COMMAND_UNSUPPORTED, API_BATCH_SHAPE,
API_BATCH_COMMAND_SHAPE, API_BATCH_REJECTED, API_TRANSACTION_SHAPE,
API_REQUEST_LIMIT, API_RATE_LIMIT, API_QUEUE_FULL, API_RESULT_PENDING,
API_RESULT_EXPIRED, API_REQUEST_REPLAY, API_REQUEST_ID_CONFLICT and
API_SEQUENCE_REQUIRED. Canonical editor validation or history conflicts may be
returned unchanged in the result code. Other API_* codes fail closed. Stop and
inspect the returned code; create a fresh pairing when the owner, client, or
pairing is gone.

Limits
Request body 48 KiB; owner result 40 KiB; pairing 120 seconds; owner lease 130
seconds; client idle 120 seconds; client absolute life 15 minutes; queued
request 30 seconds; transient full result 5 seconds; queue depth 16; active
request/result ledger capacity 64 with fixed-memory replay tombstones and
monotonic sequence rollover; rate 5 requests/second and 20 requests/10 seconds.

Excluded authority
No command can Build, Run, compile, upload, open a device, create a native
runtime or worker, access files, deploy, or grant those capabilities.
