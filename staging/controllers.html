This release contains exactly one tested profile in each displayed group: ATmega328P, RP2040 Pico, ESP32-C3 development module and STM32F429ZI. A family label never claims support for every controller in that family.

A profile lists three different things: source the compiler accepts, behavior the runtime executes, and the educational circuit model displayed on the canvas. Successful compilation does not prove every API, library or peripheral is simulated.

Language, API, headers and libraries

ATmega328P

Dialect: Arduino AVR sketch/C++ in the fixed isolated toolchain.

Files: main.ino plus up to seven project-local .h, .hpp, .c or .cpp files.

Headers: Arduino.h, standard bounded C headers, avr/io.h, avr/interrupt.h, avr/pgmspace.h, util/atomic.h and util/delay.h.

Libraries: Arduino AVR core 1.8.8 only; no user-installed or network-fetched library. Compiler acceptance does not expand the documented runtime subset.

RP2040 Pico

Dialect: strict bounded C11 in Arm GNU 14.3.1.

Files: main.c only.

API: one GPIO0 call, one UART0 uppercase-text call and halt in the fixed template.

Headers/libraries: no user-selectable headers, libraries or Pico SDK. A fixed internal contract header is injected by the worker.

ESP32-C3

Dialect: strict bounded Arduino sketch in Arduino-ESP32 3.3.10 / esp-rv32 2601.

Files: sketch.ino only.

API: fixed setup/loop template; only GPIO2 mode, level and one uppercase Serial marker may change.

Headers/libraries: no user-selectable headers or libraries, network install, Wi-Fi or Bluetooth SDK surface.

STM32F429ZI

Dialect: strict bounded freestanding C11 in Arm GNU 14.3.1.

Files: main.c only.

API: one PB0 call, one USART3 uppercase-text call and halt in the fixed template.

Headers/libraries: no user-selectable headers, HAL, CMSIS or broad STM32 SDK. Fixed startup, linker and runtime contracts remain internal.

A failed Build shows only sanitized diagnostics. When a returned error contains a trustworthy current file and line, its button focuses that exact editor location. Missing, out-of-range, stale and cross-profile locations stay visible but never navigate. See compiler diagnostic help.

Tested AVR subset

  • Digital GPIO D0–D13, input, output, and pull-up modes
  • ADC A0–A5 against bounded 0–5 V sources
  • PWM on D3, D5, D6, D9, D10, and D11
  • USART0, bounded timing, deterministic reset, and instruction stepping
  • INT0/INT1 and the implemented pin-change masks

Tested Pico subset

  • One exact bounded main.c grammar
  • GPIO0 HIGH or LOW from compiled firmware
  • UART0 uppercase text from compiled firmware
  • Source-bound strict UF2 execution in a browser worker
  • GP0 physical pin 1 through 220 Ω and LED to GND physical pin 3

Tested ESP32-C3 subset

  • One exact bounded Arduino sketch grammar
  • GPIO2 OUTPUT/INPUT and HIGH/LOW source values
  • Uppercase UART marker from two actual QEMU boot epochs
  • Fixed 4 MiB DIO flash and exact runtime identity
  • GPIO2 → 220 Ω → LED → GND in a separate project-owned model, not QEMU pin readback

Tested STM32F429ZI subset

  • One exact bounded C11 main.c grammar
  • PB0 HIGH or LOW from a strict compiler-generated ELF
  • USART3 uppercase text observed in actual Renode 1.17.0
  • Two matching boot epochs prove reset replay
  • Editable named PB0 → 220 Ω → LED → GND ideal teaching path with movement, rotation, deletion and bounded history

Not claimed

Complete cycle-perfect hardware equivalence, physical-device upload, every library, SPI, I²C/TWI, EEPROM writes, watchdog activation, analogue-comparator use, and electrical-safety certification are not part of this release.

Parts and project files in the narrow profiles

Pico, ESP32-C3 and STM32 each expose only one fixed controller, resistor.fixed-v1 and led.basic-v1. The board cannot be removed. A deleted resistor or LED can be added back with its stable ID, but no cable is inferred: reconnect the named pins yourself and Build fresh. Select an existing cable to add an orthogonal bend, move an eligible snapped section or choose one of six colours; crossings remain separate unless a declared junction dot says otherwise. All four controllers save one common data-only envelope; its exact profile identity routes Open only after validation, and Open never restores executable authority. See the exact part limits and the recovery steps.

Why the STM32 boundary is narrow

Only the fixed PB0/USART3 source grammar, strict ELF admission and reset-replayed Renode path are public. Arbitrary C or ELF, broad peripherals, SDK compatibility, physical timing, external hardware and full STM32 support remain explicitly outside this release.
