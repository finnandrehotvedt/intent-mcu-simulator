First projects for the narrow controllers

Choose Architecture / family, then the exact Tested controller / board. Each group currently has one tested profile: ATmega328P, RP2040 Pico, ESP32-C3 development module or STM32F429ZI. Keep its complete source template and edit only the values named below; these are bounded lessons, not broad family, board or SDK support.

RP2040 Pico · GPIO0 light

Goal: drive an external LED and print one UART0 marker.

Wire: GP0 physical pin 1 → series resistor → LED anode; LED cathode → GND physical pin 3.

Edit: change only GPIO0 level 0/1 and the 1–24 character uppercase UART text in the fixed main.c.

Expect: the rp2040js worker reports GPIO0, the ideal LED follows the accepted circuit, and UART0 shows your marker.

Save/Open: the download ends in .intent-mcu.json. Open restores source, parts, properties, layout and wires, but requires a fresh Build.

ESP32-C3 · GPIO2 model and QEMU UART

Goal: boot compiled flash in actual QEMU and compare its UART with the separately labelled GPIO2 LED model.

Wire: GPIO2 J1 pin 4 → series resistor → LED anode; LED cathode → GND J1 pin 6.

Edit: change only GPIO2 OUTPUT/INPUT, HIGH/LOW and the uppercase marker in the fixed sketch.

Expect: QEMU supplies CPU/UART/reset evidence. The LED comes from executed register writes in the project model; QEMU pin state is not claimed.

Save/Open: the local .intent-mcu.json common envelope contains project data only. Open retires flash/runtime authority until Build and Run succeed again.

STM32F429ZI · PB0 and USART3

Goal: compile the strict C11 source and observe PB0 plus USART3 in actual Renode.

Wire: PB0 CN11 pin 34 → series resistor → LED anode; LED cathode → GND CN11 pin 35.

Edit: change only PB0 HIGH/LOW and the uppercase USART3 marker in the fixed main.c.

Expect: Renode reports PB0 and USART3 twice across reset replay; the external LED path remains an ideal teaching rendering.

Save/Open: the local .intent-mcu.json common envelope excludes ELF and runtime state. Open requires a fresh Build before Run or Reset.

Paired working examples

Each narrow-controller workbench now offers two visible authored-data cards: output HIGH with one UART marker, and output LOW with a different marker. Loading a card never restores firmware or runtime state. Build and Run must succeed again before the LED or terminal result is authoritative. Button, ADC and PWM remain explicitly unavailable on these three narrow public profiles.

Repair after deleting a part

  1. Save the incomplete project and Open it again if you want to prove history-free recovery.
  2. In Supported parts, add the one missing resistor or LED. The fixed stable ID returns, with no cable.
  3. Activate two compatible free named pins for each missing connection. Unsafe resistance/colour pairs reject without changing the accepted draft.
  4. When the circuit state says accepted, Build fresh and Run. Old executable authority never returns from the file.
