OPEN SOURCE · VERIFIED BOUNDARIES
What is Intent MCU Simulator?
It is an original browser workbench that turns supported firmware into observable virtual hardware behaviour. Build a circuit by connecting named pins, compile edited source in an isolated fixed toolchain, then inspect GPIO, LEDs, inputs, serial bytes, and logic traces.

      

        
What does it simulate?
Four bounded controller paths: the documented ATmega328P browser subset; RP2040 GPIO0/UART0; actual ESP32-C3 QEMU CPU/UART plus a separately labelled GPIO2 model; and actual STM32F429ZI Renode PB0/USART3/reset replay plus an ideal external LED teaching path.

        
Does Prompt Bridge call AI?
No. It creates portable text for a tool you choose. Only returned structured circuit data that passes the project schema, pin rules, and electrical validation can reach the canvas.

        
Does it replace physical testing?
No. Simulation is not physical safety certification and does not claim complete timing or hardware equivalence. Verify real designs on appropriate hardware.

FIRST PROJECT · FOUR STEPS
From circuit to evidence
  1. Open an exampleChoose an AVR starter here, or follow the exact Pico, ESP32-C3 or STM32 guide.
  2. Inspect and wireMove parts, select named pins and check the electrical diagnostics. Missing narrow-profile parts return through Supported parts without inferred cables.
  3. Build, then runThe isolated compiler creates the exact firmware executed by the selected bounded runtime.
  4. Save, reopen and readThe local file keeps authored data but never executable authority. Open requires a fresh Build; then read the LED, UART and runtime evidence.
